Configuring Custom Server Protection

The CMS and appliance provide a lot of protection for your servers automatically with rules, rule sets, service protocols, profiles, and server protection that is built in to the product, supporting the essential server protection practices that are critical to keeping your network safe. To achieve the maximum possible protection for your servers, however, you will want to customize the configuration so that it is optimized for the particular traffic that your organization's network encounters. Clicking Defense Configuration in the web UI tool bar provides access to the following commands for configuring server protection explicitly:

  • Server Protection – Configure how the appliance responds to traffic bound for your servers.
  • Server Profiles – Specify traffic characteristics to associate .with servers in your network.
  • Client Groups – Specify sets of clients that should have their traffic handled the same by your appliances.
  • Client Profiles – Specify traffic characteristics to associate with clients outside your network.
  • Service Protocols – A service protocol specifies how traffic corresponding to a particular application is handled by the appliance.
  • Rule Sets – A rule set is a named collection of rules that is configured to identify and address traffic for a particular purpose.
  • IP Packet Header Blocking – Block access to your network for types of traffic that you never expect to encounter from legitimate users.
  • IP Address Shunning – Shunning is a temporary measure that refuses entry to all traffic from a specific IP address for a finite amount of time. Shunning is useful when you encounter problematic traffic from a particular IP address; you can shun the traffic from that address for a period of time until you decide on a policy for handling that traffic over the long term.
  • IP Address Blocking – Blocking an IP address completely adds that IP address to a list of addresses that is consulted before any other part of the corresponding packet is examined. A packet from a blocked address is discarded immediately, and no additional processing is performed on any portion of its contents.
  • Flex Rule based Blocking – The Flex-Rule utility provides a means of defining custom packet blocking filters. These custom filters enable you to respond quickly to new threats you encounter that are not yet addressed by formal rules in Corero’s SmartWall software, or, otherwise, to threats for which you want a very specific or nuanced response that is not provided to your liking by the built-in software.
