Service Protocol screen

Service protocols specify how traffic corresponding to a particular application is handled by the appliance, and are an essential component of server protection. Click Defense Configuration > Service Protocols to display the Service Protocol screen. Alternatively, type the CLI command set defense profiles service-protocol to access the same functionality.

A large number of service protocols are built-in to the CMS and provided by default. You can modify these built-in service protocols or define your own custom ones, as necessary. Some of these built-in service protocols correspond to legitimate applications, or to applications that otherwise are not originally intended to be attack vectors, while others correspond to specific well-known attack vectors.

Refer to Configuring Server Protection to see how service protocols are associated with server protection instances.

Each service protocol is defined by the following parameters:

  • Name – A descriptive name for the service. Built-in service protocols include the transport protocol and port in their names.
  • Description – A description that further identifies the service. This field is examined by the Search function, so it is important to add a description that will help you pick out the new service from the list of services.
  • Connection Timeout – The number of seconds without traffic for this service that the appliance should wait before timing out the connection.
  • Transport Protocol – The protocol (IP, ICMP, TCP, or UDP) used by the service.
  • Transport Port – The port number associated with the service.
  • Kind – This can be Any, Address Specification, or Host Group.
  • Address Specification – Define the server or group of servers to associate with this service. Enter a single IP address, range of IP addresses (e.g., 2.2.2.1-2.2.2.100, or 2.2.2.1/24), IP address range and port range (e.g., 221-225, 230), or combinations of these. Separate entries with commas.
    • Discard Priority – This value indicates how likely it is that the appliance will discard packets for this service during periods of extremely heavy traffic. Selecting a higher priority specifies that you want the traffic associated with this service to be more likely to be discarded. Choose High, Medium (the default), or Low.
    • Flow Setup Threshold – Modifying this setting can adversely affect system operation. Contact Corero Network Security before changing this setting. Choose Always Create (the default), Never Create, Less Than 25 Percent, Less Than 50 Percent, Less Than 75 Percent.
      This parameter indicates how critical it is to record connection information for this service. The appliance uses a flow table to record certain state information about each traffic connection. Under extreme traffic conditions, the flow table could become full.
      This parameter enables you to specify how critical it is to record connection information for a specific service. By not creating an entry in the flow table, you preserve the table for more critical services during periods of heavy traffic. For each service, you can choose whether you never want to create an entry in the flow table, or whether you always do. Alternatively, you can specify that the appliance create an entry in the table only if the table is less than a specific percentage full. This way, as the table fills, fewer flows are set up for lower priority traffic.
    • Request Limiting – Click to enable this and restrict the number of requests that can be made by this service protocol.
