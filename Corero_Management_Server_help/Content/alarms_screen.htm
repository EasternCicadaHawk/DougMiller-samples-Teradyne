Alarm Center screen

Click the alarm clock icon in the web UI status bar to display the Alarm Center screen. Alternatively, use the CLI command show alarms summary or show alarms alarm-list to see current alarm information.

Alarms indicate noteworthy occurrences related to the CMS itself or the Corero appliances that it manages. Alarms are characterized with severities ranging from Warning, indicating notifications of which you should be aware, up to Critical, indicating serious problems with the function of your server defense infrastructure. Specifically, the Alarm Center screen shows uncleared alarms; these are notifications which have not yet been addressed, whether by an action executed by a human operator, or, in some cases, by self-clearing, if the circumstance that triggered the alarm has corrected itself.

Alarm severities are assigned explicitly to the definitions of specific known types of occurrences, and are not assigned dynamically based on numerical values or the crossing of predefined thresholds. The supported alarm severities are:

  • Critical – Critical alarms are not self-cleared.
  • Major
  • Minor
  • Warning
  • Indeterminate

Alarms can be exported from the CMS via SNMP and syslog. The relevant configuration parameters are available in the Advanced Site Controls screen.

You can perform these actions on selected alarms (click the checkbox to the left of the alarm entry):

  • Compress – Show only the latest state change associated with the alarm.
  • Purge – Delete entries associated with the alarm.
  • Handle – Choose a handling method from the pulldown menu: Acknowledged, Investigation, Observation, Closed.

Clicking an alarm entry opens a panel that shows information about the alarm in greater detail:

  • Alarm Handling – Choose a handling method from the pulldown menu: Acknowledged, Investigation, Observation, Closed.
  • Status Change – This section lists the individual changes in status for the alarm.

If the storage device associated with a Forensics appliance lacks sufficient space to collect a new query, the query fails and an alarm is generated. If this happens, delete some old queries to free space for the new query.
