Best Practices For Shunning Large Numbers of IP Addresses

Problem

Block a large number of IP addresses as determined from external data sources, such as Splunk or security event lists.

Solution Overview

SmartWall IP address shunning takes a large number (tens of thousands) of source IP addresses organized into containers called "labels" and blocks all packets from those source IP addresses for a configurable period of time. After this period, these addresses are allowed through the system again. The goal of this service is to provide a short term attack mitigation capability to allow for proper diagnosis of the root cause of the attack.

It is expected that this service will be primarily configured programmatically as driven by the necessity of automated malicious source address collection, and this topic provides an example of how the SmartWall IP address shunning service can be configured programmatically.

Example

An example follows. If you want to try re-using this example with your own configuration, make sure to change names and IP addresses as appropriate.

Create the list of source IP addresses to be shunned. The required format is shown below. Note that only the first two fields in the IP address configuration list are required. In the format version 1 (shown in this example), any subsequent fields are ignored.

Step 2

Transfer the source address shunning file list named "shunip-import-test2.csv" in this example) to the CMS and place it in the /home/admin directory (the default for the admin user). Scp is shown here as a basic network system service, but other mechanisms can be used.

%[user1 ~/shun_data]$ scp -P 2222 shunip-import-test2.csv admin@10.20.27.112:~

Step 3
