Server Protection Overview

All SmartWall Threat Defense System functionality exists to protect your servers, but the term "server protection," used explicitly within the CMS, refers to the set of responses (treatments) that are configured to occur when incoming traffic matches one or more profiles associated with a service protocol for a server group. Server protection is configured per server group, and a server protection instance combines a server group (and the service protocol and profiles that it comprises) with default responses, called treatments, for traffic coming inbound to the servers and going back outbound to the clients. As a result of the nature of their components, server protection instances incorporate all aspects of CMS protection configuration, including client groups, client profiles, and rule sets, each of which is a component of a server protection instance at some level.

The default traffic treatment is Default network-wide server protection, and it is used when no other traffic treatment has been configured. This default treatment handles traffic as being Random (asymmetric), with all rules off for both security rule sets and reputation rule sets.

Server protection is configured using the Server Protection screen.
