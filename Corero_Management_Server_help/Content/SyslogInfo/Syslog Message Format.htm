Syslog Message Format

The basic syslog message as defined in RFC 5424 has many different operations and paramters. However, because most common tools are built to understand the basic syslog structure, it is not necessary to define any more than the basic header contents that are populated when syslog messages are generated by the CMS. As received and presented by a common SIEM, a basic message structure looks like:

Jan 25 17:36:03 10.20.27.202 Jan 25 17:36:01 cms2-global  < security data content >

Basic SIEM Data Format

In this example

  • Jan 25 17:36:03 10.20.27.202 is the timestamp and source of the message as received by the SIEM.
  • Jan 25 17:36:01 cms2-global is the time of message generation at the CMS and its hostname.  This is standard syslog header data prepended to the security data as the message is formatted for transmission across the network.
  • The security data content is the information described in this document.

Remembering that the date and time of these fields is the creation time of the syslog message, not the originating data, is important for proper understanding of the data.  It is very useful information because much of the received data is periodically generated by the CMS as it does its analysis of the security information it is receiving from the devices under its control so the time of generation of this data corresponds to the time of creation of the report data.
