Security Event Type

Security events are generated by the Defense Appliances as they provide the security of the system.  Security event information is sent from the appliances to the controlling CMS where they are locally processed and analyzed to provide Corero customers with immediate security state and attack information.   In parallel with this local analysis, security events are sent to configured SIEMs for historical storage and additional processing.

An example of security event syslog content is shown below:

Mar 16 11:00:59 10.20.29.52 Mar 16 11:04:47 corpit-cms.corero.com cat=security,type=event, v=1,aip=10.20.29.130,sip=126.92.201.80,sprt=50699,dip=63.239.35.219,dprt=53, dir=inbound,act=block,prot=17,defense-mode=mitigate,srvgrp=default,cust=default, rule=cns-100027, time=1394982287900979,pnum=1082468377, plen=79, pdu=00175401c9300019e23c63fe08004500004150c94000f511896b7e5cc9503fef23dbc60b0035002d89f950c901000001000000000000076261747371696c016b05797874783803636f6d00,

The specific content for the security event data is defined below:

 

Field Name

Short Name

Specific Value / Type

Description

Category

cat

security

Security event category

Type

type

event

Security event

Version

v

Number

The Corero message format version

Appliance IP

aip

IP Address

The defense appliance that originated this event

Source IP

sip

IP Address

The source IP address in the packet that resulted in the security event

Source Port

sprt

Number

The source port in the packet that resulted in the security event

Destination IP

dip

IP Address

The destination IP address in the packet that resulted in the security event

Destination Port

dprt

Number

The destination port in the packet that resulted in the security event

Direction

dir

inbound | outbound

The direction (inbound or outbound) of the packet

Action

act

block | detect

Whether the packet was blocked or just detected and not blocked

Protocol

prot

IP protocol

The IP protocol in the packet that generated this event.  Refer to the full list at http://www.iana.org/assignments/protocol-numbers/protocol-numbers.xhtml

Defense Mode

defense-mode

Text [mitigate,

          monitor,

          bypass,

          not-applicable,

          not-in-sync]

The defense mode of the protection group fro the originating Network Threat Defense appliance and the deployment mode is in-sync.  Otherwise, the values are not-applicable and not-in-sync, respectively

Server Group

srvgrp

Text

The server group for the destination IP address for this packet if a match is found in the server protection configuration.  If no match is found, “any” is used

Customer

cust

Text

The customer name for the destination IP address for this packet if a match is found in the server protection configuration.  If no match is found, “default” is used

Rule Name

rule

Text: cns-xxxxxx

The Corero security event rule that

occurred to generate this event

Timestamp

time

Microsecond time on the appliance

The timestamp on the Smartwall appliance that generates this event

Packet Number

pnum

Number

A count on the on the Smartwall appliance of the packet that generated this event

Packet Length

plen

Number

The length of the packet including the Ethernet header but not including the 4-byte CRC

PDU

pdu

Hex values

Up to 200 bytes of the pdu starting from the mac addresses

Security events generated by each Defense appliance are limited to a maximum of 5 per second per event in order to ensure that no single event will overwhelm the resources of the CMS or Splunk and mask the existence of other security events. The cat=security event=rule-stats shows the full count of the number of occurrences of each rule.
