Common keywords

There are several keywords that appear in the different messages. When these names appear, they can always be interpreted as defined below.

 

Field Name

Syslog Short Name

Definition

Category

cat

All messages start with the category of the message.  The types are security, network, system, ops, diags, rt

Type

type

Type within the category

Version

v

Version of the Corero Syslog message format

Cluster

cl

The cluster of protection-groups in which the appliance is configured.  The value “all” is used when data from all clusters are aggregated in the message

Protection Group

pg

The protection group in which the appliance is operating. The value “all” is used when data from all protection groups are aggregated in the message

Device/Appliance Name

aname

The name provisioned for a Corero Network device/appliance

IP

ip

An IP address.  It could be a source or destination based on the conString of the message

Source IP address

sip

The source IP address of a data packet that was processed in some way to create this data

Destination IP address

dip

The destination IP address of a data packet that was processed in some way to create this data

Source Port

sprt

The source IP port of a data packet that was processed in some way to create this data

Destination Port

dprt

The destination IP port of a data packet that was processed in some way to create this data

Packet Length

plen

The length of the packet including the Ethernet header but not including the 4-byte CRC

IP Packet Length

iplen

The length of the IP packet including the IP header

Rule Name

rule

The Corero security event rule name

(e.g. cns-001005)

Common Types

Multiple values or entries

When there are multiple entries associated with the data in a message, e.g. a top-sip report of the top 10 source IP addresses observed over the the last time period, the different entries are indicated by the index number appended directly to the name, e.g.

ip1=3.4.5.6,ip2=5.6.7.8,ip3=1.2.3.4,ip4=2.3.4.5. 

This is less structured than is possible in other representations of tabular data such as through an XML or JSON, but this is designed to allow for quick summarization via name* wildcarding.   More sophisticated structures can be parsed by common tools, but plugins and additional tools are often required to perform the processing.
