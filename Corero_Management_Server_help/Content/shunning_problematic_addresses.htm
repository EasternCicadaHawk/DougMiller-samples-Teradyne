Shun Problematic IP Addresses

Appliances have an effective protection capability called shunning that can quickly block traffic from IP addresses, temporarily or permanently, that are suspected of originating or participating in an attack. Shunning is described in detail in this overview. Shunning is defined via shun labels, which are containers for the list of addresses to the blocked, the time interval for which they'll be blocked, and some other characteristics for how the shunning action should work. The appliance supports up to 256 shun labels.

Click Defense Configuration > IP Address Shunning in the web UI tool bar to display the Shunning screen for configuring shunning actions. Alternatively, use the CLI command set defense shunning to access the same functionality. If you want to remove an address from shun label so that it is no longer shunned, you need to do this using the Delete Shun Address command in the Configuration Actions screen (the CLI equivalent is request config delete-shun-address address ipaddressrange).

Modify these settings to configure shunning for your site:

NOTE: If you use the CLI, remember to enter configuration mode prior to attempting any other configuration tasks. Do this by typing configure at the CLI command prompt.

Action Where to perform it What to do
Create a shun label. This is the container for the shunning action. Web UI: Defense Configuration > IP Address Shunning, then click Add to display the Shun Label screen.

CLI: set defense shunning shun-label shunlabelname

REST API: curl -k -v -u admin:admin -X POST https://[cmsipaddress]/api/running/defense/shunning -d '{"shun-label": {"label": "labelname"} }' --header "Content-Type:application/vnd.yang.data+json"

 Type a descriptive name for the shun label. In the web UI, click Create to add it to the list of existing shun labels.
Specify one or more IP addresses to block temporarily. Web UI: Defense Configuration > IP Address Shunning and select the shun label in the list.

CLI: set defense shunning shun-label shunlabelname address ipaddress
OR
set defense shunning shun-label shunlabelname file filename

REST API: curl -k -v -u admin:admin -X POST http://cmsipaddress/api/running/defense/shunning/shun-label/shunlabelname -d '{"address": "clientipaddress"}' --header "Content-Type:application/vnd.yang.data+json"

 Specify one or more IP addresses or ranges of IP addresses that you want to block. You can type the range as a spread of IP addresses (200.1.1.1 - 200.1.1.255), with a subnet mask (200.1.1.0 255.255.255.0) or as an offset (200.1.1.0/24).

For a small number of IP addresses, you can type them here by hand. For a larger list, you can specify a file that contains the list of IP addresses to be blocked.
Set a duration for the shunning action. Web UI: Defense Configuration > IP Address Shunning and select the shun label in the list.

CLI: set defense shunning shun-label shunlabelname duration durationvalue

REST API: curl -k -v -u admin:admin -X POST https://cmsipaddress/api/running/defense/shunning/shun-label/shunlabelname -d '{"duration": "durationvalue"}' --header "Content-Type:application/vnd.yang.data+json"

 Specify one of the predefined durations. These range from 5 minutes to unlimited, with 4 hours being the default.

Optional: Change the setting for whether the shunning action will supersede the behavior for an associated client group or server group.

 Web UI: Defense Configuration > IP Address Shunning and click Ignore If Configured Address.

CLI: set defense shunning shun-label shunlabelname ignore-if-configured-address [false | true]

REST API: curl -k -v -u admin:admin -X POST https://cmsipaddress/api/running/defense/shunning/shun-label/shunlabelname -d '{"ignore-if-configured-address": "false | true"}' --header "Content-Type:application/vnd.yang.data+json"

 Ignore If Configured Address indicates whether this shunning action will supersede the default behavior for an associated client group or server group. This is on by default.
Save your changes when you're finished. Web UI: Save CLI: commit REST API: Save/commit occurs automatically upon execution of the cURL command.
