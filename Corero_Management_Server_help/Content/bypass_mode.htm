Bypass Mode and Defense Mode

This topic describes the options that can be configured for Bypass mode/Defense mode.

Refer to Network Bypass Behavior for a full description of how the network bypass feature works.

Refer to Accessing Bypass Controls for instructions on where to access the Bypass mode and Defense mode controls in different configuration contexts.

The SmartWall Threat Defense System provides two configurable modes for controlling how individual clusters or the site as a whole handle serverbound traffic as they encounter it. Defense mode controls the behavior of Defense appliances, and Bypass mode controls the behavior of a Bypass appliance, if one is in use. The two modes comprise settings that control whether incoming traffic should be inspected and treated according to configured rules (Mitigate/Inline), inspected and logged according to configured rules without being treated (Monitor), or simply passed through without being touched (Bypass).

The Bypass/Defense mode can be set to one of the following states. By default, the mode is set to Monitor for newly added appliances and clusters. You must change the mode explicitly for appliances to operate in Mitigate/Inline mode.

  • Mitigate – Inspect all traffic and treat it as specified by the server protection instances that are in effect. Specifically, for each appliance type:
    • Bypass appliance – Mitigate mode is called Inline mode for the Bypass appliance. The Bypass appliance passes all traffic through, leaving it to be handled by the attached devices as they are configured to do.
    • Forensics appliance - Apply filters and record activity before passing the traffic through to attached devices.
    • Defense appliance - Inspect all traffic and pass through only good traffic, as defined by the server protection instances in effect.
  • Monitor – Pass traffic through to the servers without treating it, but log the way that server protection instances would respond to the traffic if the operational mode was set to Mitigate. Specifically, for each appliance type:
    • Bypass appliance – Copy traffic to attached devices.
    • Forensics appliance - Apply filters without recording activity, and pass the traffic through to attached devices.
    • Defense appliance – Inspect all traffic and pass it through.
  • Bypass – Pass traffic through to the servers without treating it, completely untouched, without any logging or event reporting. This mode is available only if a Bypass appliance is in use. Specifically, for each appliance type:
    • Bypass appliance – Pass through all traffic. In the event of power loss, this happens automatically as a result of the Bypass appliance's passive optical passthrough capability.
    • Forensics appliance - Pass through all traffic without applying any filters or recording any activity.
    • Defense appliance – Pass through all traffic without inspecting or treating any of it.

Depending on the context in which you are configuring the mode, two other options may be available:

  • Inherit Global – This option causes a cluster to use the Global Bypass/Global Defense setting, whatever that is configured to be.
  • Auto – The Bypass appliance determines whether it can be in Inline mode or Monitor mode, or needs to be in Bypass mode, depending on whether it is receiving heartbeat from the devices attached to it.
