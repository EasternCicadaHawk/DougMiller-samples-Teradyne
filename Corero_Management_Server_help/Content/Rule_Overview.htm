Rule Reference

Rules are an essential building block of server protection. They are constructed to identify traffic that may be suspicious in origin, malicious in intent, and harmful in its results. Some rules define very strict conditions that you may not want to apply to every host, while other rules address definite known issues that should be applied universally. You can create a named set of rules, modify the treatment applied to individual rules within the set, and then use the named rule set as a component when defining server protection instances.

NOTE: Changing rule settings can affect system operation adversely. Consult with Corero Network Security before changing these settings.

Security Event Category

Every rule begins with a five-character security event category prefix that enables you to sort by prefix anywhere a list of rules appears. Security event category prefixes and their descriptions follow. Broadly, each category describes two dimensions: whether the identified threat is application-based or network-based (this is the "APP" or "NET" portion of the prefix), and whether the nature of the threat involves access restrictions (AR), rate limits (RL), protocol validation (PV), or integrity analysis (IA).

  • ARAPP - Access Restrictions (application threats; layer 7)
  • ARNET - Access Restrictions (network threats; layer 2 through layer 4)
  • RLAPP - Rate Limits (application threats; layer 7)
  • RLNET - Rate Limits (network threats; layer 2 through layer 4)
  • PVAPP - Protocol Validation (application threats; layer 7)
  • PVNET - Protocol Validation (network threats; layer 2 through layer 4)
  • IAAPP - Integrity Analysis (application threats; layer 7)
  • IANET - Integrity Analysis (network threats; layer 2 through layer 4)

Each rule definition includes a short description and a long description.
