Configure Server SYN Flood Protection

SYN flood protection can be configured for server protection instances using the SYN flood threshold parameter. Click Defense Configuration > Server Groups and Protection in the web UI tool bar to display the Server Groups and Protection screen. Alternatively, type the CLI command set defense profiles server-profiles syn-flood-profile.

Configure server SYN flood protection:

NOTE: If you use the CLI, remember to enter configuration mode prior to attempting any other configuration tasks. Do this by typing configure at the CLI command prompt.

Action Where to perform it What to do
Configure the SYN flood limit for the server protection instance. Web UI: Defense Configuration > Server Groups and Protection in the web UI tool bar to display the Server Groups and Protection screen. Select an existing server protection instance and click the Thresholds & Limits tab. The important parameter is SYN flood threshold, which is the maximum allowable number of open SYN requests to servers in this protection instance. You can choose an existing profile from the pulldown menu and use the value that is configured there, or click Use a custom profile to set a new explicit value for this parameter.
CLI: set defense profiles server-profiles syn-flood-profile profilename connection-threshold thresholdvalue Specify the value of the SYN flood threshold via a SYN flood profile and the connection-threshold parameter.
REST API: curl -k -v -u admin:smartwall -X PATCH https://cmsipaddress/api/running/defense/profiles:profiles/server-profiles/syn-flood-profile -d '{"syn-flood-profile": {"name": "synfloodprofilename", "connection-threshold": value } }' --header "Content-Type:application/vnd.yang.data+json"
Associate the SYN flood limit with an existing server group. CLI: set defense server-protection DEFAULT servergroupname assigned-profiles syn-flood profilename Associate the SYN flood profile with the corresponding server protection instance by specifying the server group name and the SYN flood profile name. This is not necessary when using the web UI, since the profile is associated in context.
REST API: curl -k -v -u admin:smartwall -X PATCH https://cmsipaddress/api/running/defense/server-protection:server-protection/server-group/customername%2Cservergroupname/assigned-profiles -d '{"assigned-profiles": {"syn-flood": "profilename" } }' --header "Content-Type:application/vnd.yang.data+json"
Save your changes when you're finished. Web UI: Save CLI: commit REST API: Save/commit occurs automatically upon execution of the cURL command.
