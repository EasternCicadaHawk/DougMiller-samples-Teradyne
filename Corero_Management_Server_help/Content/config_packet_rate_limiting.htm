Configure Packet Rate Limiting

Packet rate limiting restricts the number of packets that servers can accept from one or more clients in a time interval. It is based on an upper limit on the number of packets that can be accepted from clients in a particular client group with a particular client profile. This is a credit-based mechanism in which the credits are replenished over time, so a client is not restricted perpetually if its traffic diminishes and falls within the configured limit.

In previous releases of Corero software, packet rate limiting was known as client request rate limiting, or CRRL.

Configuring packet rate limiting combines elements of client group configuration and service protocol configuration.

To configure packet rate limiting:

NOTE: If you use the CLI, remember to enter configuration mode prior to attempting any other configuration tasks. Do this by typing configure at the CLI command prompt.

Action Where to perform it What to do
Assign client IP addresses to a client group. Web UI: Defense Configuration > Client Groups to display the Client Group screen, then click the Address Ranges tab. Select an existing client group or create a new one. Specify one or more singleton addresses or specify an address range to associate with the group.
CLI: set defense profiles client-groups client-group clientgroupname client-addresses ipaddressrange
REST API: curl -k -v -u admin:smartwall -X POST https://cmsipaddress/api/running/defense/profiles/client-groups/client-group/clientgroupname -d '{"client-addresses": {"ip-address": "ipaddressrange"} }' --header "Content-Type:application/vnd.yang.data+json"
Configure the packet rate limit profile. Web UI: Defense Configuration > Client Profile to display the Client Group screen, then click the Thresholds & Limits tab. The important parameter is Maximum packet rate for any client in this group. You can choose an existing shared profile from the pulldown menu and use the value that is configured there, or click Use a custom profile to set a new explicit value for the parameter.
CLI: set defense profiles client-profiles packet-rate-limit-profile clientprofilename limit limitvalue Specify an existing packet rate limit profile and use the limit value that is configured there, or define a new packet rate limit profile with a custom limit value.
REST API: curl -k -v -u admin:smartwall -X PATCH https://cmsipaddress/api/running/defense/profiles:profiles/client-profiles/packet-rate-limit-profile -d '{"packet-rate-limit-profile": {"name": "profilename", "limit": value } }' --header "Content-Type:application/vnd.yang.data+json"
Optional, for a custom client profile: Export the custom client profile for re-use later. Web UI: Click the link at the bottom of the Thresholds & Limits tab to display the Add New Shared Profile dialog. Type the name of the file to which you want to export the profile settings.
Enable request limiting. Web UI: Defense Configuration > Service Protocols, and select an existing service protocol to edit it, or create a new one. Enable Request Limiting. In the web UI, click the option in the Service Protocol screen; in the CLI, set the value of request-limiting to true.
CLI: set defense profiles service-protocol serviceprotocolname request-limiting true

Optional: Modify the costs for packet types.

NOTE: Use caution when increasing the per-packet cost of any packet type. Increasing the cost of a specific packet type can increase the packet cost of a session significantly, and when you multiply that by many sessions, the total cost can accumulate quickly. This may result in legitimate traffic being blocked unintentionally.

 Web UI: Defense Configuration > Advanced Security Controls to display the Advanced Controls screen. Type costs for individual packet types.
CLI: set defense profiles advanced-controls packet-costs
Save your changes when you're finished. Web UI: SaveCLI: commit REST API: Save/commit occurs automatically upon execution of the cURL command.
