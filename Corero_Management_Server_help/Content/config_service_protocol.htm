Configure a Service Protocol

A service protocol specifies how traffic corresponding to a particular application is handled by the appliance. A large number of service protocols are built-in to the CMS and provided by default. You can modify these built-in service protocols or define your own custom ones, as necessary. Some of these built-in service protocols correspond to legitimate applications, or to applications that otherwise are not originally intended to be attack vectors, while others correspond to specific well-known attack vectors.

Click Defense Configuration > Service Protocols in the web UI tool bar to display the Service Protocol screen for defining service protocols. Alternatively, type set defense profiles service-protocol in the CLI.

To configure a service protocol:

NOTE: If you use the CLI, remember to enter configuration mode prior to attempting any other configuration tasks. Do this by typing configure at the CLI command prompt.

Action Where to perform it What to do
Name a new service protocol. Web UI: Defense Configuration > Service Protocols to display the Service Protocol screen, then click Add.

CLI: set defense profiles service-protocol serviceprotocolname

REST API: curl -k -v -u admin:smartwall -X POST https://cmsipaddress/api/running/defense/profiles:profiles/service-protocols -d '{"service-protocol": [ {"name": "serviceprotocolname" } ] }' --header "Content-Type:application/vnd.yang.data+json"

 In the web UI, click Create to add the service protocol to the list.

Note the large number of predefined service protocols. You may find the one that you need in the list already, without having to create a new one.

Specify the transport protocol and transport port, as well as a connection timeout.

 Web UI: Click the service protocol name to edit it.

CLI: set defense profiles service-protocol serviceprotocolname transport-protocol protocolname transport-port portnumber

REST API: curl -k -v -u admin:smartwall -X PATCH https://cmsipaddress/api/running/defense/profiles:profiles/service-protocols/service-protocol -d '{"service-protocol": {"name": "serviceprotocolname", "connection-timeout": value, "transport-protocol": "value", "transport-port": "value" } }' --header "Content-Type:application/vnd.yang.data

 Specify a transport protocol, connection timeout value, and transport port.
Configure any other service protocol parameters you want to change from their defaults. Web UI: Click the service protocol name to edit it.

CLI: set defense profiles service-protocol serviceprotocolname

 See the parameter descriptions in the Service Protocol screen topic for details.
