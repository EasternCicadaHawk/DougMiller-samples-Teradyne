Configure the CMS

The CMS manages appliances and policy configurations that protect your servers and other critical resources inside your organization's firewall from DDoS attacks and cyber threats, and also protects and optimizes the performance of critical infrastructure such as servers and firewalls. This overview describes how the CMS does this.

  • Basic CMS setup and configuration checklist. This is a list of steps most users will need to perform to define a minimal working configuration.
  • Add a Corero appliance for the CMS to manage.
  • Save your configuration.
  • Optional and Advanced Configuration. These topics cover configuration tasks that are outside of a minimal working configuration.

Analyze Traffic

  • Use the CMS dashboard to see overall status for the site. The dashboard is displayed by default when you log in to the CMS.
  • View blocked and detected events. Rules can log traffic (detect it), allow it to pass through, or block it completely. These events are from the traffic your appliances are detecting and blocking.
  • View security events. Generally, traffic generates a security event every time it triggers a rule (this can vary according to the details of your configuration). This shows you all of the security events that have been generated.

Restrict Access

These are temporary measures that enable you to block malicious traffic immediately, while you define one or more policies to implement a more sophisticated long-term solution.

  • Block Specific IP Headers. Block traffic outright, based on its packet header type.
  • Block IP Addresses. Block an IP address completely by adding it to a list of addresses that is consulted before any other part of the corresponding packet is examined. A packet from a blocked address is discarded immediately, and no additional processing is performed on any portion of its contents.
  • Smart-Rule. Configure threshold values and rate limits for protecting servers from various types of flood traffic.
  • Flex-Rule. Define custom packet-blocking filters that enable you to respond quickly to new threats you encounter that are not yet addressed by formal rules in Corero's SmartWall software, or, otherwise, to threats for which you want a very specific or nuanced response that is not provided to your liking by the built-in software.

Define Policies For Long Term Protection

The appliance uses profiles to determine the acceptability of traffic seeking entry to your servers, and responds to that traffic based on server protection instances that you define.

  • Configure client profiles. These are sets of traffic characteristics that the appliance uses to distinguish between acceptable and unacceptable traffic coming in to the network.
  • Configure server protection instances. These are assemblies of profiles and responses that are associated with particular servers to guard them from DDoS attacks and cyber threats.
  • Block traffic based on its country of origin. If you know that you don't have any legitimate users in a particular country, you can just block all traffic from that country's IP address ranges.
