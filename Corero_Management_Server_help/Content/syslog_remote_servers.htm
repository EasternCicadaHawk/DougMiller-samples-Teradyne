Syslog and Splunk Configuration screen

Clicking CMS > Syslog & Splunk Configuration in the web UI tool bar displays the Syslog and Splunk Configuration screen. This screen provides controls for specifying recipients of the CMS's event and log data, such as a Splunk indexer that will be used with Corero's SecureWatch Analytics application. The same functionality is available through the CLI commands set syslog remote-server and set syslog splunk-forwarder.

The Syslog and Splunk Configuration screen provides these controls:

Syslog Servers – Click the Add button to specify a new syslog server, and provide the following information to define it.

  • Name – A descriptive name for the syslog server.
  • Host – The IP address or domain name of the syslog server.
  • Port – The port on which the syslog server will listen for events. By default, this is 514, the commonly used syslog port.
  • Protocol – The Transport layer protocol used to carry the syslog messages to the server; choose UDP (the default) or TCP.

Splunk Forwarder - This controls the forwarding of event and log data from the CMS to listening Splunk indexers. The sending of events and logs is disabled by default; choose Enabled for each, as you require.

Splunk Indexers - Specify the Name, Host [IP address or domain name] and Port of one or more Splunk instances that will receive event and log data from the CMS and index it. The port defaults to 9997, the commonly used Splunk indexing port.

Syslog Message Controls – These controls enable you to configure the behavior of some of the message types sent from the CMS via Syslog.

  • Type Event Message Limit – Maximum number of security event syslog messages sent per second per rule.
  • Type Event Send Detected – Enable sending of syslog messages for detected events. (This is Enabled by default.)
  • Type Sflow Message Limit – Maximum number of Sflow syslog messages sent per second per direction.
