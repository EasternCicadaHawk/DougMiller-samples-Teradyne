SYN Flood Attack

Definition

A SYN flood attack is a volumetric attack, a flood of TCP SYN requests directed at a target with the intent of consuming all of its available TCP connections, leaving none available for legitimate traffic. This common attack abuses the design of TCP's three-way handshake for establishing a valid connection between a client and a server.

The ordinary, legitimate behavior of the three-way handshake works like this: a client seeking a connection to a server sends that server a TCP-SYN request. The server responds to the client with a SYN-ACK message, acknowledging that it has received the client's request for a connection, and indicating that it is capable of accepting a connection. The client responds to the server with an ACK of its own, and the connection is established, enabling traffic to flow between the client and the server.

In the case of a SYN flood attack, the client never responds with that final ACK message, leaving the server with that connection assigned to the client, but not carrying any actual traffic, because the three-way handshake was never completed. A SYN flood attack does this on a massive scale, seeking thousands of new connections, often sending the initial TCP SYN requests with spoofed IP addresses. The server sends its SYN-ACK messages to potentially thousands of purported clients, none of which respond with an ACK message because none of them actually sent a TCP SYN request in the first place. The result is that all of the server's possible connections are consumed, leaving none available for real users.

The TCP SYN fragment attack is a variation on the SYN flood attack that uses incomplete TCP SYN messages.

Observable characteristics

An excessively large number of open SYN requests.

Method of response

Drop the first SYN packet from an unknown host during a DDoS attack.

CMS configuration steps

None. SYN flood protection is enabled by default.
