AAA (Authentication, Authorization, and Accounting) Overview

The closely related functions authentication, authorization, and accounting are referred to collectively as "AAA." AAA configuration is described in Configuring User Accounts and Authentication; the controls used to perform AAA administration are described in the Users & Authentication screen.

AAA configuration defines how individual users and groups of users are enabled to access the CMS and managed devices, as well as which actions they are allowed to execute once they gain access.

The authentication described here is local authentication; that is, authentication based on credentials specified in the CMS configuration itself, rather than credentials specified in an external authentication regime such as Active Directory or RADIUS. By default, the CMS looks for authentication credentials locally, first, before looking for credentials at an external server.

In any case, whether the authentication regime in use is local or external, once a user authenticates successfully, that user is matched to a group. The user's access privileges are determined from the authorizations defined for the group.

The CMS supports a set of groups that correspond to essential roles:

  • admin – Access all aspects of the data models required to manage users, devices, data, etc. This group is intended for administrators who require privileges to define and change all aspects of the configuration. Note that admin users can change passwords for all accounts, including support users.
  • defense – Configure server defense policies and view configurations, statistics, and reports.
  • monitor – View configurations, statistics, and reports. No configuration actions are allowed.
  • support – This group is reserved for use by Corero customer support. Similarly, screens and commands that are available to support users are reserved for use by Corero customer support, and are not described in this help set. Note that admin users can change passwords for support users.

The CMS comes with two predefined users; admin and support, each corresponding to the role of the same name.
