Blocking vs. Shunning

Superficially, IP address blocking and shunning appear to exhibit the same behavior and accomplish the same results. Both actions prevent packets from a specified IP address from reaching a protected server. There are important differences between them, however, as summarized here:

IP Address Blocking Shunning
Permanent. The IP address is always blocked, unless or until the address is explicitly removed from the list of addresses to be blocked. Temporary. The IP address is blocked until a user-configured time interval expires.
Use blocking if you are receiving a very large number of packets from an address. If you need detailed information about the packets coming from that address, it may be better to shun the address, instead. Use shunning if the number of packets from an address is relatively small, and you need detailed information about which packets are shunned.
Blocking actions are executed before shunning actions. Shunning actions are executed after blocking actions.
Blocking does not trigger a rule. Shunning triggers a unique rule associated with the shun label. Since shunning is executed after blocking, an address that is both blocked and shunned will not result in the triggering of a rule.
A blocked IP address is listed in the Blocked & Detected Events screen.

A shunned IP address is listed in the Security Event Viewer, up to 5 events per second.
