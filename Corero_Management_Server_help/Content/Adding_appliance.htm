Adding a Corero Appliance to Manage

A Corero appliance has to be added to the site in order for the CMS to be able to manage it. Corero appliances include all members of the SmartWall product family, including SmartWall Network Threat Defense Appliance, SmartWall Network Threat Defense Appliance, SmartWall Threat Defense System, and SmartWall Threat Defense System.

Note that adding an appliance does not cause any existing configuration to be pushed to it. The configuration must be pushed to the new appliance using Save in the web UI or commit in the CLI. This is described in the instructions for saving your configuration.

Modify these settings to add a Corero appliance to a site:

NOTE: If you use the CLI, remember to enter configuration mode prior to attempting any other configuration tasks. Do this by typing configure at the CLI command prompt.

Action Where to perform it What to do
Specify the new Corero appliance to add to the site, and specify the cluster and protection group to which the appliance belongs, as well as its position (physical location) relative to the other appliances in the protection group. Web UI: Site Configuration > Cluster Configuration > Add to display the Add a New Cluster dialog. The web UI combines these tasks in the Add a New Cluster dialog. Specify the appliance and define the cluster and protection group to which it belongs, along with the appliance's position in the equipment rack.
  • Cluster Name – Type a unique descriptive name for the cluster you are adding.
  • The Cluster Has A – Indicate whether your appliances operate individually or in a redundant (HA) configuration.
  • Each Protection Group Looks Like – Choose a representation of the set of appliances you are adding to the site.
  • The Device Settings Are – Type the IP address and a descriptive name for each appliance you are adding. For a Forensics appliance, click Forensics Settings to display a set of pop-up fields for specifying the IP address and subnet mask for port 3 and port 4.
The protection group name is added automatically, and is based on the cluster name that you specified.
CLI: set devices device descriptivename address ipaddress module-type moduletype

set site topology-settings cluster clustername protection-group groupname module devicename

 The CLI requires you to use two separate commands to do this; one to add the appliance, and another to specify its cluster, protection group, and position in the equipment rack. Add the appliance using the set devices command, and specify the cluster, protection group, and position using the set site topology-settings command.
REST API: curl -k -v -u admin:smartwall -X POST https://cmsipaddress/api/running/devices -d '{"device": {"name": "descriptivename", "address": "ipaddress"} }' --header "Content-Type:application/vnd.yang.data+json"

curl -k -v -u admin:smartwall -X PATCH https://cmsipaddress/api/running/cs:site/topology:topology-settings/cluster -d '{ "cluster": [ {"name": "clustername", "protection-group": [ {"name": "protectiongroupname", "module": [ { "name": "devicename", "position": 1 } ] } ] } ] }' --header "Content-Type:application/vnd.yang.data+json"

 As with the CLI, you need to execute two separate cURL commands to add the appliance and specify its cluster, protection group, and position in the equipment rack.
Note that adding an appliance does not cause any existing configuration to be pushed to it. The configuration must be pushed to the new appliance using Save in the web UI or commit in the CLI. This is described in the instructions for saving your configuration.
