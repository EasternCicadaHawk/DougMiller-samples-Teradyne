Introduction to the CMS Protection Model

The server protection provided by the appliance and CMS comprises four basic sets of features, each of which supports essential server protection practices:

  • IP Packet Header Blocking – Refuse entry to traffic based on its IP header type. This can be IPv4, IPv6, or IP tunnels. By default, each of these header types is allowed; you can change one or more to be blocked. This method is immediate and complete, refusing entry to all such traffic without additional examination.
  • IP Address Shunning – Refuse entry to traffic based on its IP address. Shunning is an immediate and temporary action that enables you to deny access to a problematic IP address for a finite period while you decide what to do about traffic from that address over the long term.
  • Security Profiles – Profiles are sets of conditions and limits for characterizing traffic behavior. Profiles can be configured for clients and for servers, and include collections of characteristics such as rule sets and service protocols that help to associate traffic with particular applications and assess its nature. Profiles are used with server protection, which comprises the set of responses that the appliance has available for handling server-bound traffic. When server-bound traffic matches a profile, server protection responds to that traffic and handles it in some specified way.
  • Server Protection – Server protection comprises the set of responses that the appliance has available to handle server-bound traffic that matches a profile.
