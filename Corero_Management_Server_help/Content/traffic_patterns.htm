Traffic Patterns

A traffic pattern describes the anticipated behavior of the traffic flows the Defense appliance encounters. Asymmetric traffic occurs when multiple flows between a client and server use different routes to reach each other.

Some protection features are not supported for asymmetric traffic, or are supported with variations, due to the fact that the Defense appliance may not see all of the significant packets in the flow.

Traffic patterns are components of traffic treatments. The traffic pattern is configured as part of defining a server protection instance. The traffic pattern is Symmetric by default.

The Defense appliance supports these traffic patterns:

  • Symmetric – A single Defense appliance receives all of the packets of any flow it observes. This is the default option. This mode supports all protection features.

    The client request and server response for the flows traverse through the same Defense appliance. In this mode, the Defense appliance can behave as a proxy and act upon each new SYN connection request coming into the network for clients not in a fully trusted state. The complete three-way handshake is between the client and the Defense appliance. Once the three-way handshake is established, the three-way handshake for the TCP connection is then set up between the appliance and the server.

  • One-way – [Asymmetric] If the network configuration around the Defense appliance is such that there is more than one path between a client and server, and it is possible to predict, with a low margin of error, which path through the network a flow’s packets will follow, after the initial packet of the flow is observed.

    In this traffic pattern, the client requests always take a predictable path, but the responses may traverse a different path. The Defense appliance will force a non-trusted client to re-initiate a SYN connection request after the client has already sent in the first SYN connection request by forcing a reset of the TCP connection (the appliance responds back initially with a SYN ACK with an invalid sequence number).

    The client state of untrusted to trusted or untrusted to malicious is still based on the number of outstanding open SYNs awaiting completion of the three-way handshake from the client, since the client ACK must always be received by the Defense appliance.

    For this mode to work, all the client requests must go through the Defense appliance.

  • Random – [Asymmetric] There is no way to predict the path that a flow's packets will take. Load-balancing is one possible cause of this situation.

    In this traffic pattern, there is no way to predict the path for a given request or response. This mode assumes everything is already a mid-flow much like a power-up state. It is possible to classify a client as malicious (no suspicious classification possible). Fragmentation exploit inspection is not possible (automatically disables IP Fragmentation assembly for system when enable random asymmetric mode for a server group)

    No TCP proxy is supported in this mode.
