Configuring Server Protection

Server protection comprises the set of responses that occur when incoming traffic matches one or more profiles.

Server protection is configured per server group; a server protection instance combines a server group (and the service protocol and profiles that it comprises) with default responses, called treatments, for traffic coming inbound to the servers and going back outbound to the clients. Due to the nature of their components, server protection instances incorporate all aspects of CMS protection configuration, including client groups, client profiles, and rule sets, each of which is a component of a server protection instance at some level.

Click Defense Configuration > Server Groups and Protection in the web UI tool bar to display the Server Groups and Protection screen. Alternatively, type the CLI command set defense server-protection to access the same functionality.

The CMS provides a single built-in server group named, "Default network-wide server protection". This is a default, catch-all server group that implicitly contains all server IP addresses that are not explicitly included in another server group. To be clear: a server IP address that is not explicitly included in a user-defined server group is implicitly included in the built-in server group named, "Default network-wide server protection". You cannot specify explicit IP addresses for this server group, and it has treatments associated with it only, not server profiles. It is necessary to define a server group explicitly to be able to use a server profile.

Modify these settings to configure server protection:

NOTE: If you use the CLI, remember to enter configuration mode prior to attempting any other configuration tasks. Do this by typing configure at the CLI command prompt.

Action Where to perform it What to do
Create a server group. Web UI: Defense Configuration > Server Groups and Protection in the web UI tool bar to display the Server Groups and Protection screen. Click Add to display the Add New Group dialog.

CLI: set defense server-protection server-group customername servergroupname

REST API: curl -k -v -u admin:smartwall -X POST https://cmsipaddress/api/running/defense/server-protection:server-protection -d '{ "server-group": {"customer": "customername", "server-group-name": "servergroupname" } }' --header "Content-Type:application/vnd.yang.data+json"

 Create the new server group by specifying an existing customer to associate with it (choose DEFAULT if you do not have other customers associate with your site) and typing a descriptive name. In the web UI, make sure to click Add in the Add New Group dialog to finish creating the server group.
Specify the addresses of the servers that belong to the server group, or members of any IP address range subsets that you want to define. Web UI: Select the name of an existing server group in the Server Groups and Protection screen, then click Add in the Address Ranges tab to display the Add IP Address Range dialog.

CLI: set defense server-protection server-group DEFAULT servergroupname server-addresses ipaddressrange

REST API: curl -k -v -u admin:smartwall -X POST https://cmsipaddress/api/running/defense/server-protection:server-protection -d '{ "server-group": {"customer": "customername", "server-group-name": "servergroupname" {"server-addresses": "ipaddressrange" } } }' --header "Content-Type:application/vnd.yang.data+json"

 Specify one or more server IP addresses to include in the server group. You can type individual addresses or a range of addresses (e.g., 2.2.2.1-2.2.2.100, or 2.2.2.1/24).
Configure the SYN flood threshold and connection limits for the server group. This is the server profile. Web UI: Select the name of an existing server group in the Server Groups and Protection screen, then click the Thresholds & Limits tab.

CLI: set defense profiles server-profiles [connection-limit-profile | syn-flood-profile]

 Choose an existing profile or specify custom values as necessary. The values are explained in the Server Group and Protection screen.

Specify an existing profile by name or specify custom values as necessary. Note that the CLI exposes that the threshold and limit values are actually divided between different types of profiles.

When using the REST API, note that both profile types must be created using the same profile name in order for the server profile to be associated with a server protection instance.

Specify the client group and protocol group from which the server group is being protected, and specify the treatment to be used for traffic from those clients.

This involves client groups and service protocols that are configured separately.

 Web UI: Select the name of an existing server group in the Server Groups and Protection screen, then click the Server Protection tab. Click Add to display the Add Traffic Treatment dialog. Add Traffic Treatment dialog box:
  • Choose an existing protocol group
  • Choose an existing client group
  • Click Next to display the Protocol Group/Client Group dialog box

Protocol Group/Client Group dialog box:

  • Choose an action for the server protection instance (Allow or Block).
  • Select an existing security rule set
  • Select an existing reputation rule set
  • Click Issue Security Event if you want to generate an event
  • Choose an event severity if you are generating an event
  • Click OK to finish defining the server protection instance
CLI: set defense server-protection server-group DEFAULT servergroupname service-protocol-group serviceprotocolname client-group clientgroupname treatment [action | admin-state | comments | event-severity | security-ruleset | issue-security-event | reputation-ruleset | traffic-pattern] It's possible to define the server protection instance in a single command line, though it's not necessary to do so. You can break up the configuration over multiple command lines if you find that easier.

Specify the server group, then specify the service protocol and client group of interest, along with the treatment to be applied for traffic of that type originating from those clients.
Save your changes when you're finished. Web UI: Save CLI: commit REST API: Save/commit occurs automatically upon execution of the cURL command.
