How Traffic is Evaluated Against a Server Protection Instance

Server protection instances specify the criteria by which traffic coming in to your servers from clients outside your firewall is evaluated for being treated by the Defense appliance. A server protection instance comprises a server group (a set of server IP addresses collected together for common traffic treatment), one or more service protocols, and one or more client groups. As traffic is encountered, it is evaluated against the definition of the server protection instance in this order:

  1. server IP address
  2. service protocol
  3. client group

A server IP address can belong to a single server group only, and this guarantees that inbound traffic will match some permutation of the server protection instance conclusively. The matching traffic will be allowed, dropped, or blocked, as specified by the server protection instance.

The table below describes the order in which incoming traffic is evaluated against the server protection instance to identify a match with a treatment. The order of evaluation goes left-to-right, then top-to-bottom.

Order Server IP Service Prot Client Group
1 Specific Specific Specific
2 Specific Specific Any
3 Specific Any Specific
4 Specific Any Any
5 Any Specific Specific
6 Any Specific Any
7 Any Any Specific
8 Any Any Any

"Any" functions as a catch-all or wildcard. For any component of the server protection instance (server IP address, service protocol, or client group) it is evaluated for a match last, after every explicit definition has been tried.For server groups, it corresponds to "Default network-wide server protection", and for client groups, it corresponds to "IP addresses not in a specific group". In the table above, incoming traffic that matches a specific server IP address, a specific service protocol, and a specific client group is matched with a traffic treatment immediately. Incoming traffic that does not match any specific server IP address, service protocol, or client group receives the default, last-resort treatment that is specified for traffic that matches no specific component of the server protection instance. Other incoming traffic will match criteria somewhere between those two extremes, and will be treated accordingly.

Some examples follow, with the corresponding traffic treatments shown.

This example shows a simple case of a single server group. a single service protocol group, and three client groups, each with a different treatment. DNS traffic to DNS servers from Trusted Clients is allowed through, DNS traffic to DNS servers traffic from Known Bad Clients is blocked outright, and all other DNS traffic to DNS servers is detected, meaning that it is logged.

Server Group Service Protocol Group Client Group Treatment
All DNS Servers DNS Trusted DNS Clients Allow
    Known Bad Clients Block
    Any Detect

The next example expands on the previous one, with the addition of the "Any" server group (Default network-wide server protection) and an ICMP service protocol group. The example is largely the same as the previous one, except that ICMP traffic [e.g., ping] is blocked, regardless of its destination server or its originating client.

Server Group Service Protocol Group Client Group Treatment
All DNS Servers DNS Trusted DNS Clients Allow
    Known Bad Clients Block
    Any Detect
Any ICMP Any Block

The next example is a little more elaborate, adding a server group for HTTP servers, with a few "Any" entries for service protocol group and client group. Stepping through the three server groups from top to bottom:

  • For All HTTP Servers:
    • HTTP traffic from clients in undesired countries of origin is blocked completely.
    • ICMP traffic from any client is allowed.
    • Any other traffic bound for the HTTP servers is blocked.
  • For ALL DNS Servers: see the first example.
  • For Any server not included in All HTTP Servers or All DNS Servers:ICMP traffic from any client is blocked completely.

Remember that an IP address, whether for a server or a client, can be included in a single server group or client group only. In this example, if a server IP address is not included explicitly in All HTTP Servers or All DNS Servers, it defaults to being in the Any server group.

Server Group Service Protocol Group Client Group Treatment
All HTTP Servers HTTP Geo Bad Clients Block
  ICMP Any Allow
  Any Any Block
All DNS Servers DNS Trusted DNS Clients Allow
    Known Bad Clients Block
    Any Detect
Any ICMP Any Block

Catch-All

There is a catch-all server group for all server addresses not included in any other group. This server group cannot be disabled, and all rules associated with it are disabled. Packets arriving on the external port for which the destination address is not part of any server group are silently allowed to transit through the appliance. This catch-all server group is not shown in the CMS.
